## B. Ultralytics — YOLO26 文档页

来源：<https://docs.ultralytics.com/models/yolo26/> 〔读页〕

### B.1 Overview（原文）

> Ultralytics YOLO26 is the latest evolution in the YOLO series of real-time object detectors, engineered from the ground up for **edge and low-power devices**. It introduces a streamlined design that removes unnecessary complexity while integrating targeted innovations to deliver faster, lighter, and more accessible deployment.
>
> The architecture of YOLO26 is guided by three core principles:
>
> - **Simplicity:** YOLO26 is a **native end-to-end model**, producing predictions directly without the need for non-maximum suppression (NMS). By eliminating this post-processing step, inference becomes faster, lighter, and easier to deploy in real-world systems. This breakthrough approach was first pioneered in YOLOv10 by Ao Wang at Tsinghua University and has been further advanced in YOLO26.
> - **Deployment Efficiency:** The end-to-end design cuts out an entire stage of the pipeline, dramatically simplifying integration, reducing latency, and making deployment more robust across diverse environments.
> - **Training Innovation:** YOLO26 introduces the **MuSGD optimizer**, a hybrid of SGD and Muon — inspired by Moonshot AI's Kimi K2 breakthroughs in LLM training. This optimizer brings enhanced stability and faster convergence, transferring optimization advances from language models into computer vision.
> - **Task-Specific Optimizations:** YOLO26 introduces targeted improvements for specialized tasks, including semantic segmentation loss and multi-scale proto modules for **Segmentation**, Residual Log-Likelihood Estimation (RLE) for high-precision **Pose** estimation, and optimized decoding with angle loss to resolve boundary issues in **OBB**.
>
> Together, these innovations deliver a model family that achieves higher accuracy on small objects, provides seamless deployment, and runs **up to 43% faster on CPUs** — making YOLO26 one of the most practical and deployable YOLO models to date for resource-constrained environments.

### B.2 Key Features（要点原文）

- **DFL Removal** — 移除 Distribution Focal Loss 模块，简化推理、扩大边缘/低功耗设备兼容。
- **End-to-End NMS-Free Inference** — 原生端到端，预测直接产出。
- **ProgLoss + STAL** — 提升精度， notably 小目标识别。
- **MuSGD Optimizer** — SGD+Muon 混合。
- **Up to 43% Faster CPU Inference**。
- Instance Segmentation / Pose / OBB 各自的增强（略，见原文）。

### B.7 Dual-Head Architecture（原文要点）

> - **One-to-One Head (Default)**: Produces end-to-end predictions without NMS, outputting `(N, 300, 6)` with a maximum of 300 detections per image.
> - **One-to-Many Head**: Generates traditional YOLO outputs requiring NMS post-processing, outputting `(N, nc + 4, 8400)`.
>
> You can switch between heads during export, prediction, or validation（`end2end=False`）。

>
> ### NVIDIA CUDA
> … uninstall onnxruntime, install onnxruntime-gpu … repeat the replacement afterward …
>
> ## Quick Example
> ```python
> import cv2
> from insightface.app import FaceAnalysis
> from insightface.data import get_image
> app = FaceAnalysis()
> app.prepare()
> image = get_image("t1")
> faces = app.get(image)
> cv2.imwrite("t1_output.jpg", app.draw_on(image, faces))
> ```
> `FaceAnalysis()` defaults to `buffalo_l` and downloads the model package on first use if needed. Models are stored under `~/.insightface/models/` by default. `prepare()` uses `ctx_id=0` and Auto detection size, combining 128×128 and 640×640 detection.
>
> ### Match people in a video（cheetah_s）
> ```python
> import math
> import cv2
> from insightface.app import PersonAnalysis
> analysis_fps = 2  # Analyze at most twice per video second to speed up processing.
> cap = cv2.VideoCapture("clip.mp4")
> try:
>     if not cap.isOpened():
>         raise RuntimeError("Cannot open clip.mp4")
>     source_fps = cap.get(cv2.CAP_PROP_FPS)
>     if not math.isfinite(source_fps) or source_fps <= 0:
>         raise ValueError("The video must report a valid frame rate")
>     frame_step = max(1, math.ceil(source_fps / analysis_fps))
>     with PersonAnalysis(name="cheetah_s") as app:
>         registration = app.register("employee_001", "alice.jpg")
>         if registration.accepted == 0:
>             raise ValueError(f"No reference was accepted: {registration.rejected}")
>         frame_index = -1
>         while True:
>             ok, frame = cap.read()
>             if not ok:
>                 if frame_index < 0:
>                     raise RuntimeError("The video opened but did not return a readable frame")
>                 break
>             frame_index += 1
>             if frame_index % frame_step:
>                 continue
>             matches = app.match(app.get(frame))
>             app.update(matches)  # Optional: learn body references after clear face matches.
>             for result in matches:
>                 print(f"{frame_index / source_fps:.2f}s", result.person_id, result.matched_by)
> finally:
>     cap.release()
> ```
> A 30 FPS video analyzes every 15th frame. …
>
> ### Automatic Provider selection
> ```text
> CoreMLExecutionProvider → CUDAExecutionProvider → CPUExecutionProvider
> ```
> PersonAnalysis defaults to CPU and also supports explicit CUDA selection. …

> ## PersonAnalysis
> … Use `register()` to add reference photos, `get(frame)` to extract observations, `match(observations)` to find matching IDs, and optional `update(matches)` to learn body references after clear face matches. … Choose `cheetah_s` for the smaller model package or `cheetah_l` for the larger one. … Results describe the current frame; the API does not create tracks or a history database.

## L. Debian 13 + uv + Python 3.14（搜索摘要）

来源：Web 搜索结果汇总（docs.astral.sh 等）〔摘要〕

- 生产使用托管 Python 的权衡（2024 年起的社区讨论）指出其主要适用于此类自包含服务场景。

## M. RustFS（S3 兼容对象存储）〔v2 补充〕

来源：<https://rustfs.com>、<https://github.com/rustfs/rustfs>（经 Web 搜索汇总）〔摘要，非逐字〕

- RustFS：Rust 编写、分布式、S3 兼容对象存储；**Apache 2.0** 许可；定位为 MinIO 的现代替代（尤其对照 MinIO 更严的许可变化）。
- 里程碑：2024-02 首次提交；2025-07 开源；**2026-09 发布 v1.0.0（GA）**；搜索时 ~36k stars、4.2M+ 实例、23M+ Docker 拉取、160+ 贡献者。
- 能力（要点）：桶/对象生命周期、分片上传、纠删码（Reed-Solomon）、数据分层、S3 Tables（Iceberg REST）；多协议（S3 兼容 API、WebDAV、Swift、FTP/FTPS、MCP）；安全（IAM/OIDC/KMS、SSE-S3/KMS/C、STS、mTLS、审计）；高可用（分布式、扩容、再平衡、自愈、站点/桶复制）。
- 快速开始：
  - `curl -O https://rustfs.com/install_rustfs.sh && bash install_rustfs.sh`
  - `docker run -d -p 9000:9000 -p 9001:9001 -v $(pwd)/data:/data rustfs/rustfs:latest`
  - Web 控制台 `http://ip:9001`；S3 客户端连 `9000`。
- 备注：另有一个无关的同名小项目（SuperInstance/rustfs，单二进制 S3 服务），本项目不采用。上表数字来自搜索汇总，实施时以官方文档/README 为准。

## N. 企业微信群机器人 API 约束〔v2 补充〕

来源：企业微信官方开发者文档/社区问答（经 Web 搜索汇总）〔摘要，非逐字；实施时以官方文档为准〕
官方文档入口：<https://developer.work.weixin.qq.com/document/path/91770>（群机器人 webhook）

- **频率限制：每 webhook（每机器人）20 条/分钟**，全部消息类型统一计数；超限返回 `api freq out of limit`；约 1 分钟后恢复。理论日上限 28800 条；官方未提及月/日总量限制。
- 超限常被误报，实际多可追溯到真实调用频率；被限流后间隔一分钟重试。
- **图片消息**：仅支持 JPG、PNG；base64 前 ≤2MB。两种方式：① `msgtype: image` 直接带 base64；② 先 `upload_media` 上传取 `media_id`（+md5）再发（上传接口文件限制 5B~20M；media_id 3 天有效）。
- 单机器人不够用：同群添加多个机器人组成 webhook 池轮询（如 3 个 → 60 条/分钟）；或队列化限速（Python asyncio 队列等）。
- 相关第三方库可参考（本项目计划直接用 httpx 不引依赖）：pywgb、weworkbot、wecom-notifier。

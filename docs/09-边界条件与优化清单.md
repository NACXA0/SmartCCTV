## Part A · 边界条件

### A1. 视频接入与摄像头

| # | 边界条件 | 应对（标注） |
|---|----------|--------------|
| 1 | 摄像头断流/弱网/半开连接 | ffmpeg `-rtsp_transport tcp` + `-rw_timeout 5s -stimeout 5s` + `-reconnect 1 -reconnect_streamed 1 -reconnect_delay_max`；读线程按"stdout 无帧 N 秒"判定假死并重启子进程；指数退避 + 随机抖动（防多路同时重连风暴）〔核心〕 |
| 2 | 码流时间戳异常/漂移 | `-fflags +genpts -reset_timestamps 1 -use_wallclock_as_timestamps 1`（连续录像进程）；分析侧按到达序 + 单调序号丢弃乱序帧〔核心〕 |
| 3 | 子码流分辨率与配置不符 | 首帧校验尺寸，动态适应；RTSP 多 profile 自动探测（主/子码流 fallback）〔建议〕 |
| 4 | 摄像头重启/DHCP 换 IP | 文档建议静态 IP/MAC 绑定；摄像头面板对超时路标红 + 事件〔建议〕 |
| 5 | URL 错误/重复添加 | 添加时 5s 超时试连校验；按 URL+路径去重〔核心〕 |
| 6 | 服务器时间不准/时区 | README 要求启用 systemd-timesyncd；**时间戳统一 UTC 存储、本地时区仅显示**；夏令时无影响〔核心〕 |
| 7 | 全黑/全白/花屏/镜头被遮挡/被转动 | 帧亮度+方差检测 → "画面异常"事件（防破坏告警）〔建议〕 |
| 8 | 本地文件源（联调用 mp4） | ffmpeg `-re` 按原速读；文件结束自动循环；无摄像头联调路径〔核心（测试用）〕 |

## Part B · 性能优化（缓存/流程）

### B1. 管线流程

1. **解码与分析解耦**（已规划）：单读线程 + latest-frame 总线；补充：暴露**丢弃率**指标（读入帧 vs 分析帧），面板可查背压〔已规划+〕。
2. **活动检测前置闸门**（帧差/背景减除）：静止画面直接跳过 YOLO/SCRFD——省 CPU 大头（多数时间场景静止）；事件密度低时收益最大；阈值保守防漏检〔核心〕。
3. **分析帧率自适应**：按时间段（夜间安静 0.5-1fps）+ 事件密度（活动时瞬时提频到 5fps）双因子；每路独立〔建议〕。
4. **推理批处理（可选）**：多路帧聚合 batch 推理可提吞吐 1.3-2×，代价是延迟与复杂度——列为性能挡位开关，默认关闭〔可选〕。
5. **torch 线程控制**：单进程单模型；`torch.set_num_threads` 设物理核数；`OMP_NUM_THREADS` 与 onnxruntime `intra_op_num_threads` 一致协调，避免超订〔核心〕。
6. **零拷贝路径**：ffmpeg stdout 读入复用同一 buffer；JPEG 编码只拷必要区域；避免逐帧 `np.copy`〔建议〕。
7. **ffmpeg 侧**：`-threads` 限制每路解码线程（如 1-2）防多路互踩；子码流分辨率即最大优化；Intel VAAPI 硬解列为可选实验（兼容性风险，默认关闭）〔建议/可选〕。

### B2. 缓存层（明细）

| 缓存对象 | 方案 | 失效 |
|----------|------|------|
| 人脸库 embedding | 全量常驻内存（<100 人时向量矩阵），暴力余弦微秒级 | DB 变更（注册/删除/改名）时重载 |
| 事件列表缩略图 | 落盘生成小尺寸 jpg 缓存（如 320px） | 原抓拍删除时级联清理 |
| 事件/门禁列表分页 | **keyset 分页**（时间游标），避免大表 OFFSET | — |
| 回放分段索引 | 每路 segment 列表内存缓存 | 新分段产生/清理时更新 |
| 前端静态资源 | Vite 内容 hash + `Cache-Control: max-age=31536000`（dist 由 FastAPI 托管） | 发版自然失效 |
| MJPEG 流 | 强制 `Cache-Control: no-cache`，禁止任何代理缓存 | — |
| 低频 API（camera 列表/配置） | 服务端短 TTL 内存缓存 + SSE 通知失效 | 配置变更时 |
| SQLite 索引 | events(cam_id,ts)、recordings(ts)、door_logs(ts)、persons 主键 | — |

### B3. 启动/资源/关闭

1. **启动顺序**：DB/配置 → 录像进程（先能录）→ ffmpeg 分析进程（先能看）→ 模型**懒加载**（首路分析时加载，启动秒开）；ffmpeg 并发启动限速〔核心〕。
2. **平滑关闭**：SIGTERM → 停读线程 → 对 ffmpeg 发停止指令并等待 segment 收尾写 moov → 关 DB；超时强杀兜底；START.sh stop 调用该路径〔核心〕。
3. **资源指标**：每路分析延迟/丢弃率/进程 RSS + 总 CPU/内存 → 面板系统页 + 日志（性能回归可观察）〔建议〕。
4. **磁盘布局**：录像按天分区目录（YYYY/MM/DD），控制单目录文件数〔建议〕。

## Part C · 安全（代码安全 / 鉴权安全）

### C1. 鉴权与会话

1. TOTP 校验：±1 时间窗口；**已用 code 缓存（防重放）**；失败计数与日志〔核心〕。
2. 登录暴力破解限速：按 IP + 全局两层限速，失败递增退避（如 5 次失败后 30s 锁）〔核心〕。
3. 会话：itsdangerous（HMAC-SHA256）签名 Cookie；**HttpOnly + SameSite=Strict + Secure（未来 TLS 后开启）**；7 天滑动续期〔核心〕。
4. 会话吊销：**重置 TOTP 密钥 = 轮换签名 secret + session 版本号，全部会话立即失效**〔核心〕。
5. CSRF：SameSite 兜底 + 非简单请求校验自定义头（如 `X-Requested-With`）；敏感 POST 检查 Origin〔建议〕。
6. 内部接口隔离：健康检查/调试接口绑定 localhost 或需会话〔建议〕。

### C2. 代码安全

1. **命令注入**：ffmpeg 一律 `subprocess` 参数列表（禁 `shell=True`）；URL/路径参数白名单化（协议仅 rtsp/http(s)/file）〔核心〕。
2. **路径穿越**：所有落盘路径 `Path.resolve()` 后校验在数据根目录内；文件名白名单字符集〔核心〕。
3. **输入校验**：全部 API 用 Pydantic 模型；规则多边形点数/坐标范围、上传文件类型+大小上限、时段配置合法性〔核心〕。
4. **错误信息**：生产模式不向前端回显 traceback/内部路径；日志本地完整记录〔核心〕。
5. **日志脱敏**：RTSP URL 中的 user:pass、门禁 webhook KEY、S3 凭证一律打码后落日志〔核心〕。
6. **响应头**：CSP `default-src 'self'`（+ MJPEG/SSE 同源）、`X-Content-Type-Options: nosniff`；React 默认转义防 XSS〔建议〕。
7. **服务降权运行**：systemd 以专用非 root 用户运行；数据目录 0700〔建议〕。
8. **网络暴露面**：默认绑定 0.0.0.0 供内网，但文档给出 ufw/nftables 收敛方案；端口非默认（8300）〔建议〕。

### C3. 密钥与数据安全

| 密钥/数据 | 措施 |
|-----------|------|
| TOTP secret / 会话签名 secret / RTSP 密码 / 门禁 KEY / S3 凭证 | 全部独立文件 0600；启动时校验权限并告警；支持环境变量注入替代文件〔核心〕 |
| 人脸向量（生物特征） | DB 与备份同视为敏感数据：备份加密（age/openssl）或至少 0600；删除人员的级联清除策略（A2#17）〔建议〕 |
| 模型文件 | 下载后 SHA-256 校验（insightface 包 manifest 校验习惯；YOLO 权重手动核对）〔核心〕 |
| 依赖供应链 | `uv sync --frozen` 部署；定期 `pip-audit`/`uv` 审计；升级前备份〔建议〕 |
| 备份流程 | START.sh 备份 = DB + config + 人脸库（排除录像）；恢复流程文档化并演练〔建议〕 |

## Part D · 更多优化方向（路线图）

### P1（**v4 起已纳入首期必备**）

1. **以图搜人**：上传/点选一张脸 → 时间范围内找同一人的所有出现（SQLite 向量暴力搜索即可实现）。
2. **事件时间轴联动**：某事件一键跳到**所有摄像头**的同一时刻（"前后 30 秒"快切）。
3. **人数统计报表**：每日峰值/时段热力图（复用现有检测数据聚合）。
4. **系统自检页**：ffmpeg/模型/DB/S3/通知 逐项亮灯 + 一键诊断日志。
5. **前后门双门禁**：架构天然支持，配置第二门口机 + 第二继电器即可。
6. **声光告警**：门禁适配器扩展（继电器驱动喇叭/警灯），夜间入侵即时声响。

### P2（更大特性，按需评估）

7. **跌倒检测**：yolo26n/s-pose（CPU 开销与 detect 同档，见 03 文档基准）。
8. **烟雾/火焰检测**：保留上游特色，YOLO26 上可做，但误报率高——默认关闭、独立模型可选。
9. **车牌识别**：门口有车道时的可选模块（第三方 ONNX）。
10. **人脸活体插件**：InsightFace 2.x liveness 模型路线（见 04 文档 §3），提升防冒充。
11. **移动端 PWA**：Service Worker 缓存外壳 + 响应式宫格 + 系统通知。
12. **只读分享链接**：无 TOTP 的只读视图（若日后有访客场景；注意引入最小权限语义）。
13. **双机/异机备份**：录像 rsync 到 NAS 或第二台机（S3 外置即已覆盖冷备场景）。
14. **Prometheus `/metrics`**：可选导出，接内网监控栈（无监控栈则不需要）。

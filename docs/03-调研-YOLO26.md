# 03 · 调研：YOLO26（检测/跟踪模型选型）

> 调研时间：2026-11-24。来源：Ultralytics 官方文档站与 GitHub Releases（原文摘录见 [08-原始资料存档.md](08-原始资料存档.md)）。
> 结论先行：**YOLO26n/s（CPU + torch）替代原仓库的 YOLOv5 + DeepSORT**，跟踪用 ultralytics 内置 ByteTrack。

---

## 1. 关键事实速览

| 项 | 事实 |
|----|------|
| 发布 | **2026-01-14**，Ultralytics 当前最新一代（YOLO27 尚无发布时间表） |
| 定位 | 官方称 "the latest Ultralytics release and the only one covering all seven tasks"；为**边缘/低算力设备**重新设计 |
| 免 NMS | **原生端到端（NMS-free）**：默认 one-to-one 头直接输出 `(N, 300, 6)`，最多 300 个检测；可选 `end2end=False` 切回需 NMS 的 one-to-many 头 `(N, nc+4, 8400)` |
| 架构简化 | **移除 DFL 模块**——简化导出、扩大边缘硬件兼容面 |
| CPU 提速 | 官方口径 "up to **43% faster CPU inference**"（对比 YOLO11） |
| 许可 | **AGPL-3.0**（或 Ultralytics 企业许可）。个人内网自用无碍 |
| 任务覆盖 | detect / seg(实例+语义) / depth / cls / **pose** / obb + 各任务 tracking；开放词汇版 YOLOE-26 |
| 包版本 | ultralytics v8.4.218（2026-11-23），近期仍持续优化 CPU ONNX 推理 |

## 2. 官方基准（COCO，复制自文档；CPU ONNX Intep Proc N)

### Detection（640 输入）

| Model | mAP^val 50-95 | mAP 50-95 **(e2e)** | Speed CPU ONNX | T4 TRT10 | params | FLOPs |
|---|---|---|---|---|---|---|
| YOLO26n | 40.9 | 40.1 | **38.9 ± 0.7 ms** | 1.7 ms | 2.4M | 5.4B |
| YOLO26s | 48.6 | 47.8 | **87.2 ± 0.9 ms** | 2.5 ms | 9.5M | 20.7B |
| YOLO26m | 53.1 | 52.5 | 220.0 ± 1.4 ms | 4.7 ms | 20.4M | 68.2B |
| YOLO26l | 55.0 | 54.4 | 286.2 ± 2.0 ms | 6.2 ms | 24.8M | 86.4B |
| YOLO26x | 57.5 | 56.9 | 525.8 ± 4.0 ms | 11.8 ms | 55.7M | 193.9B |

### Pose（COCO，仅 person 一类）

| Model | mAP^pose 50-95 (e2e) | mAP^pose 50 (e2e) | Speed CPU ONNX |
|---|---|---|---|
| YOLO26n-pose | 57.2 | 83.3 | **40.3 ± 0.5 ms** |
| YOLO26s-pose | 63.0 | 86.6 | **85.3 ± 0.9 ms** |
| YOLO26m-pose | 68.8 | 89.6 | 218.0 ± 1.5 ms |

> 选型解读：m 档以上 CPU 耗时跃升（>200ms），不适合多路；**n（~39ms）与 s（~87ms）是本项目的甜点档**。pose 版为二期跌倒检测预留，CPU 开销与同档 detect 几乎相同。

## 3. 用法（官方示例原文要点）

```python
from ultralytics import YOLO

model = YOLO("yolo26n.pt")          # 预训练 COCO 权重，首次自动下载
results = model.predict("image.jpg")  # 默认端到端、无需 NMS
results = model.predict("image.jpg", end2end=False)  # 切 one-to-many（需 NMS，略高精度）
```

- 导出：`model.export(format="onnx")`（亦支持 OpenVINO/TensorRT 等；v8.4.214 刷新过含 YOLO26 CPU/Core Ultra 基准的 OpenVINO 指南）。
- 跟踪：predict 之上开 `tracker="bytetrack.yaml"` 即得稳定 track id（detect/seg/pose/obb 均支持），**直接取代 vendored DeepSORT**。
- P2/P6 仅有 YAML 架构无预训练权重；`yolo26-p2.yaml`（小目标头）/`yolo26-p6.yaml`（大输入）需自行训练。

## 5. 替换 YOLOv5 + DeepSORT 的理由

1. **CPU 提速**：YOLO26 为边缘/CPU 优化的新一代（免 NMS、去 DFL、官方 43% 口径），对比 vendored YOLOv5（2021 年代栈 + PyTorch 2.6 兼容 monkeypatch）。
2. **省掉 vendored 代码**：ultralytics 一包搞定 detect+track（ByteTrack），可整体 `git rm backend/yolov5 backend/deep_sort_pytorch`。
3. **维护性**：原仓库需手写 letterbox/NMS/scale_coords/sys.path 注入/torch.load 补丁；ultralytics API 一行推理。
4. **任务扩展**：后续跌倒检测换 `yolo26n-pose` 即可，同一包同一 API。

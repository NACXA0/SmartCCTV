# SmartCCTV — 内网智能监控系统重构计划

## Context

现有仓库是 fork 自 Video-analytics-pro 的 demo 级项目：`backend/` 约 300 行 FastAPI 代码（单摄像头、全局变量状态、YOLOv5+DeepSORT vendored、模拟 IoT 线程），`frontend/` 是 React/Vite/Tailwind 的单页仪表盘（5 个组件，axios 轮询 + MJPEG `<img>`）。目标是改造成运行在无 GUI Debian 单机上的家庭/内网智能监控：**≤10 路 RTSP 摄像头、纯 CPU、人脸库+门禁联动、行为风险预警、TOTP 登录（无 RBAC）、域名 cctv.lobn、uv+Python 3.14、START.sh 交互式菜单**。

用户已确认：门禁硬件未购（接受推荐）、已有 RTSP/ONVIF 摄像头、个人自用（可用 InsightFace 官方模型）、混合录像（门口 24/7 + 室内事件录）。

## 技术选型（PyPI wheel 均已一手核实，glibc≥2.28 即可）

| 组件 | 选择 | 依据 |
|---|---|---|
| 运行时 | uv + Python 3.14.x | torch 2.15.0 / onnxruntime 1.31.1 均有 cp314 manylinux_2_28 wheel；opencv-python 4.13.0.92 为 cp37-abi3 |
| 检测/跟踪 | `ultralytics` + torch-cpu，**YOLO26n/s**（替代 YOLOv5+DeepSORT） | 2026-01 发布，原生免 NMS、官方称 CPU 快 43%；n=39ms、s=87ms@640 |
| 人脸 | **绕开 insightface pip 包**（PyPI 停更于 0.7.3、仅 sdist），直接 onnxruntime 加载 `buffalo_l` 的 ONNX：SCRFD-10G 检测 + ArcFace R50 识别，自写约 300 行胶水 | LFW 99.83%；零编译、零 ABI 风险 |
| 视频接入 | 每路一个 ffmpeg 子进程：RTSP(TCP) → 子码流解码 → rawvideo 管道供分析；MJPEG 自行 JPEG 编码推浏览器；门口 24/7 录像用独立 ffmpeg `-c copy` 分段（近零 CPU） | 解码走 ffmpeg 不占 Python GIL |
| 行为分析 | 检测+ByteTrack 轨迹上的几何规则：区域入侵、越线、徘徊(时长)、人员聚集(计数)；跌倒检测留二期（yolo26-pose） | CPU 可靠、误报可控 |
| 存储 | SQLite（SQLAlchemy+aiosqlite）：人员/人脸向量(BLOB)、事件、录像索引、门禁日志 | 规模小、零运维 |
| 认证 | pyotp 单一 TOTP + itsdangerous 签名 Cookie 会话 | 按需求无 RBAC |
| 前端 | 保留 React 19+Vite 8+Tailwind 4 技术栈重写；`vite.config.js` 加 `/api` 代理；构建产物 `frontend/dist` 由 FastAPI StaticFiles 托管；事件用 SSE | 现栈现代且小 |
| 门禁 | HTTP 型网络继电器适配器（接口抽象，预留 GPIO/MQTT 实现）；定位：**智能的执行末端**（控制平面最小化，事件驱动，开门路径不经过 AI） | 见下方硬件推荐；v6 见 07 §20 |
| 部署拓扑 | 单台本地物理机；MVP 单进程直跑（任务级隔离+看门狗），演进到 Docker Compose 分容器（door/vision/web），按服务拆、不按机器拆 | 三段演进与拆分触发器见 07 §20.2 |
| 存储分层 | SQLite 管元数据；录像/抓拍本地盘为热层；**可选 S3 冷层**：默认内置单节点 **RustFS**（Docker，Apache-2.0），或配置指向外部 S3 兼容端点 | 事件片段/超期连续录像按策略上传；前端经服务端流式回源（Range） |
| 通知 | **极简告警输出模块**（v6 降级，1-2 天）：Gotify 推送（自托管，默认）+ 企业微信 webhook（可选第二通道）；级别过滤/去重/冷却 | 完整通知形态（矩阵/digest/审计）移出本项目；SSE/面板仍为主通道 |
| 调度/削峰 | `scheduler.py` + `jobs` 表（幂等可续跑）+ 全局 load gauge：谷期执行重活、峰期让路 | 负载画像/峰值统计供容量规划；digest 与预热由调度器触发 |

## 实施步骤

1. **脚手架与清理**：`git rm -r backend/yolov5 backend/deep_sort_pytorch screenshots` 等旧物；建 uv 工程（`uv python pin 3.14`）、config.yaml 加载、SQLite 模型、START.sh 骨架；重写 README。
2. **视频链路**：cameras.py（ffmpeg 子进程守护/自动重连、子码流、latest-frame 总线）、`/api/cameras/{id}/mjpeg`（服务端画检测框）、前端登录页+宫格实况。摄像头源支持 `rtsp://` 与本地文件（便于无摄像头联调）。**兼容红外夜视**：管线不假设彩色帧（灰度输入直接处理），按帧亮度自动判定昼夜并给事件打标签，每摄像头支持夜间档案（分析频率/规则阈值，见 07 §10）。
3. **检测与行为预警**：detect.py 接入 YOLO26（person 等类过滤）、ByteTrack；rules.py 四类规则 + 事件落库 + SSE 推送前端弹窗/浏览器通知；区域编辑器（在快照上画多边形/线）。**事件通知子系统（`notify/`）**：企业微信机器人适配器（text/markdown/图片消息、按事件类型分级+冷却、20 条/分钟限流队列、失败退避重试），与 SSE/浏览器通知双通道（见 07 §11）。**通知（v6 降级为极简告警输出）**：事件 → 级别过滤（默认 warning+）→ 去重/冷却 → **Gotify 推送（自托管，默认）**，企业微信 webhook 作可选第二通道；完整通知形态（矩阵/digest/审计推送）移出本项目（见 01 §9、07 §20.5）。**人数统计（`stats.py`，P1）**：检测流按分钟桶聚合写入 `detection_stats`（不逐帧入库），供统计报表页（趋势折线/时段热力图/峰值排行，recharts）。
4. **人脸与门禁**：SCRFD+ArcFace ONNX 管线；FaceDB（人员 CRUD、多照片注册、摄像头抓拍注册）；门口摄像头识别 → 白名单匹配（阈值+连续帧确认+防照片冒充的活体可后加）→ HTTP 继电器开门 5s，陌生人徘徊告警；门禁日志页。**门禁定位（v6）**：智能的执行末端——控制平面最小化（事件驱动、无 AI 同步依赖、AI 崩溃不影响物理按钮开门），为未来预约小程序的 token/二维码开门预留 schema 字段但不实现（见 07 §20.3/§20.4）。**夜间（红外）策略**：人脸识别在灰度/IR 画面下精度下降——默认夜间采用更严匹配（更高阈值/更多连续帧）或降级为"仅记录告警+手动开门"，均可配置；事件带 day/night 标记。**以图搜人（`search.py`，P1）**：入口一——从人脸库选某人查其全部出现；入口二——从事件抓拍选一张脸查相似出现（阈值可调）；embedding 常驻内存矩阵 + 时间范围过滤，结果跳转对应回放。
5. **录像**：门口 `-c copy` 每 10 分钟分段 + 索引；室内事件触发前后各 N 秒片段；留存清理定时任务；前端时间轴回放/下载。**存储分层（`storage.py`）**：本地盘为热层；可选内置单节点 RustFS（Docker，Apache-2.0）或外部 S3 兼容端点作冷层——事件片段与超期连续录像按策略上传归档，前端经服务端流式回源（支持 Range，见 07 §9）。**全摄像头时间轴联动（P1）**：按时间取帧/切片接口（连续录像 `-ss` 精确 seek），前端多路对齐同步回放；无录像时段明确标注"该路此时段无录像"。**资源治理（`diskmon.py`）**：容量账本配额 + 水位状态机（OK/WARN/CRITICAL），临界停录、恢复自动续录（见 07 §12）。
6. **认证、自检与运维**：TOTP（首次启动生成密钥+终端二维码）、会话中间件、绑定 0.0.0.0:8300；**系统自检页（`health.py`，P1）**：DB/模型/各路 ffmpeg/磁盘水位/时间同步/S3/企业微信 逐项红绿灯 + 一键诊断 + 测试通知按钮；**START.sh 六组菜单**（见 07 §13：环境检测/环境修复/运行〔终端直跑·Docker·systemd〕/维护〔重建录像索引·重置密钥·备份恢复·清理归档·诊断包〕/自动化测试/帮助，whiptail 与纯文本双渲染、`--ci/--yes` 非交互）；systemd unit（专用非 root 用户、`MemoryMax`、Restart=on-failure）；cctv.lobn 说明（内网 DNS 或 hosts 指向本机）。**Web 韧性（v5）**：会话数量上限（默认 20）+ 单 IP 限速（5）；Web 与核心管道隔离——核心任务带心跳看门狗，高压力按 **P0 录像/门禁/告警 > P1 分析 > P2 观看/搜索 > P3 谷期重活** 降级链让路，Web 崩溃不影响核心（默认同进程+看门狗，预留拆进程，见 07 §17）。
7. **自动化测试**（分层，见 07 §15）：单元层——pytest（规则几何/余弦匹配/SCRFD 后处理/config 加载/TOTP 窗口与防重放/通知模板，无重依赖）；端到端冒烟——`scripts/smoke_test.sh`（file 源 30 秒 → health 全绿 → 检测事件入库 → MJPEG 200 → SSE 收到事件）；`START.sh test [--ci]` 一键执行；可选 GitHub Actions（ruff + pytest，torch 等重依赖不进 CI）。

8. **长期运行治理**（长久运行目标，见 07 §12）：磁盘容量账本（各类数据硬配额+每小时清理器+`diskmon` 状态机）、内存账本（latest-frame 单槽/缩略图 LRU 上限/子进程并发上限/systemd `MemoryMax` 硬闸）、DB 归档与 WAL checkpoint、日志轮转、每日巡检（integrity 快检/孤儿进程与临时文件清理/配额报告/可选企业微信日报）。**削峰填谷（v5）**：`scheduler.py` + `jobs` 表——谷期（时间窗或低负载）执行可延迟重活（S3 上传/缩略图/时间轴索引/统计预聚合/备份/VACUUM），峰期让路；负载画像（分钟采样+小时聚合）输出**历史/预测/实时峰值**三层供容量规划（见 07 §16）。**网络韧性（v5）**：企业微信/S3 出站熔断器 + 通知磁盘溢写（恢复补发、超龄可弃）；RTSP 断流与卡顿分级告警（见 07 §18）。

9. **范围与演进路径（v6）**：本项目边界 = 内网监控 + 监控智能 + 极简告警输出 + 门禁执行末端；**移出**：预约小程序（未来云端独立项目，仅立关联契约：本地主动外连/云零入站端口/幂等扣时/生物特征不出内网）、通知完整形态、多门店/会员。部署**按服务拆、不按机器拆**：MVP 单进程（任务隔离+看门狗+降级链）→ 预约系统上线或门禁关键化时 Docker Compose 拆 door/vision/web 三容器 + 总线升级 mosquitto → 性能或合规触顶再上第二台物理机/NAS（触发器见 07 §20.2）。

## 门禁硬件推荐（写入 README）

HTTP 控制型网络继电器模块（如 KMtronic、亿微联/亿佰特网络继电器，局域网 GET/POST 触发），继电器**常开触点并联在门禁面板"开门按钮"两端**：不动原有门禁逻辑、断电即锁（fail-secure）、延迟可配置；可选门磁接输入干接点回读状态。

- `uv run pytest`、`uv run ruff check`。
- `./START.sh` → 安装 → 启动；浏览器开 `http://localhost:8300`（本机联调也可 `npm run dev` 走 5173 代理）。
- 无摄像头时用 `file:///...mp4` 或 ffmpeg 模拟 RTSP 源验证：画面、检测框、规则触发、事件入库/SSE。
- 人脸：注册自己照片 → 对镜头识别 → 观察门禁日志与（mock）继电器调用 → 前端回放门口连续录像分段。
- 夜视：切换红外/夜视模式，验证灰度帧检测、昼夜判定与夜间档案生效。
- 通知：触发各类事件（入侵/徘徊/门禁/系统）验证企业微信机器人收到消息（含抓拍图片）。
- S3 分层：事件片段按策略上传 RustFS 后，本地删除仍可从前端回放（Range 回源）。
- 冒烟：`START.sh test` 全绿（单元 + 端到端 smoke）。
- P1 功能：以图搜人命中、多摄像头时间轴同步回放、统计报表出图、自检页各项亮灯。
- 资源治理：人为填盘/压内存场景下系统降级不崩溃，恢复后自动续录（07 §12 场景）。
- 韧性演练（v5）：kill -9 Web / 压满并发 / 慢客户端 / 断外网——核心录像与告警不中断；会话达上限新登录被拒；断网期间通知落盘、恢复后补发（或按策略丢弃）。
- 开门路径韧性（v6）：停掉 vision 模块（模拟 AI 崩溃）后物理按钮/手动开门照常；事件总线 schema 版本化校验通过。
- 性能核对：8 路下 `htop` 观察（预计解码 ~1.5 核 + YOLO ~0.7 核 + 人脸 ~0.2 核，现代 6 核 CPU 富余）。

## 注意事项

- 模型许可：InsightFace 模型为非商业研究用途（个人自用无碍）；YOLO26 为 AGPL-3.0（自用不分发无碍）；在 README 注明。
- 内网明文 HTTP + TOTP 已满足需求；如需 TLS 后续可加 caddy 反代（不在本期）。
- insightface PyPI 包不引入；若未来想省代码可试 GitHub 2.x 源码安装作为可选依赖组。
- RustFS 为 Apache-2.0，内置/商用均无 AGPL 顾虑（区别于 Garage/MinIO 服务端）。
- 企业微信机器人：需服务器出站访问 `qyapi.weixin.qq.com`（纯隔离内网不可用）；单机器人 20 条/分钟（可在同群挂多个机器人轮询扩容）；markdown 消息不支持 @提醒，@ 需用 text 类型 `mentioned_list`。
- 夜间人脸精度受限：门口机建议补可见光照明或采用夜间降级策略（07 §10）。
- **边界条件、性能与安全的完整检查清单见 [09-边界条件与优化清单.md](09-边界条件与优化清单.md)（v3，实施时逐项对照）。**
- Docker 与终端直跑共用同一数据目录，**禁止并发双跑**（START.sh 切换模式时自动检查）。
- 所有无界增长点（录像/事件表/日志/缓存/队列）均设配额——原则见 07 §12。
- 核心/Web 隔离默认"同进程 + 心跳看门狗"（简单可靠），拆进程方案预留但不默认——避免过度设计（07 §17）。

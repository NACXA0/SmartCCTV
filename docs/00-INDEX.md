## 调研过程记录（保留全部过程细节）

这一节如实记录调研是怎么做的，包括失败的部分，供日后评估材料可信度。

### 代码库探查

1. **先并行派了 4 个只读探索 agent**（分别负责：后端链路、React 前端、YOLO/IoT/部署资产、本机环境+PyPI wheel 核实）。
2. **4 个 agent 全程卡死**：3 个卡在 `git log` 等 Bash 命令上（疑似权限队列挂起），1 个卡在对 PyPI 的 curl 网络请求上（本机到 PyPI/GitHub 的直连链路当时不稳定，多次连接超时）。尝试 TaskStop 终止也被当时所处的计划模式拦截。
3. **改为人工只读探查**：用 Read 工具直接读取关键文件。目录列表无法用 ls 获得（Bash 受限、Node REPL 内核 cwd 失效无法启动），因此**文件清单是从 README、import 语句和路径猜测+验证得出的**，属于已知不完整（详见 02 文档开头的"覆盖范围与局限"）。
4. 成功读取的文件：`README.md`、`requirements.txt`（根目录）、`backend/main.py`、`backend/vision_engine.py`、`backend/sensor_manager.py`、`backend/shared_state.py`、`frontend/package.json`、`frontend/vite.config.js`、`frontend/src/App.jsx`、`frontend/src/components/VideoFeed.jsx`。全文见 02 文档。
5. **后记**：文档整理收尾时，那 4 个 agent 因 5 小时限额耗尽而失败，但其各自**最后一条结果**提供了有价值的交叉印证（git 全史仅 4 提交、从无 Node 后端、vendored yolov5 为 v6.x 快照等），已补记入 02 文档 §0 的后记。

### 外部资料调研

- 本机直连 `docs.ultralytics.com`、`github.com`、`pypi.org` 的 WebFetch 反复超时；改用远程抓取通道（web reader 服务）后全部成功。
- 成功抓取的页面（原文存档见 08 文档）：
  - Ultralytics 模型总览页、YOLO26 文档页、GitHub releases 列表
  - InsightFace 主 README、python-package README（2.1）、model_zoo.md、runtime.md
  - PyPI：torch、onnxruntime、opencv-python、insightface 四个包的项目页/JSON API
  - Debian 13 + uv + Python 3.14 的可行性资料（搜索摘要）
- 所有版本号、发布日期、wheel 文件名均为**当次一手核实**，不是凭记忆。

### 关键结论一览（各文档有展开）

- 现有代码是 demo 级（后端 ~300 行、单摄像头、模拟 IoT），生产化建议重写为主、保留前端技术栈。
- YOLO26（2026-01-14 发布）替代 YOLOv5+DeepSORT：免 NMS、CPU 提速至多 43%。
- InsightFace **PyPI 包停更于 0.7.3（2023-04，仅源码包）**；推荐绕开该包、直接用 onnxruntime 加载 buffalo_l 的 ONNX 模型。
- Python 3.14 关键依赖 wheel 全部可用（torch 2.15.0 cp314 / onnxruntime 1.31.1 cp314 / opencv 4.13.0.92 abi3），仅需 glibc ≥ 2.28。
